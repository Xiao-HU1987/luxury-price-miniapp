# 比惠小程序版本更新记录

## v1.2.2（2026-10-02）

> 价格提醒、商品对比、收藏、浏览历史关联失效修复；价格提醒输入框点击区域修复。

### 一、价格提醒关联失效修复
- 原因：云函数 `getPriceAlerts` 中 `.filter(a => a.product)` 过滤了商品联查失败的提醒，导致提醒列表为空
- 修复：移除过滤逻辑，未找到商品的提醒保留返回，前端通过 `getProductDetail` 兜底补充商品信息

### 二、商品对比关联失效修复
- 原因：云函数 `getCompareList` 中 `.filter(Boolean)` 过滤了商品联查失败的对比项
- 修复：未找到商品的对比项返回 `{ productId }`，前端 `loadCompareList` 增加 `getProductDetail` 兜底

### 三、收藏、浏览历史同类问题修复
- 云函数 `getFavorites`、`getHistory` 移除 `.filter(Boolean)`，改为返回 `{ productId }` 由前端兜底
- 删除重复的旧版 `getFavorites`、`getHistory` case 语句（旧版只返回纯 ID，阻止新版商品联查执行）

### 四、价格提醒输入框点击区域修复
- 原因：输入框 `padding: 8rpx 0` 过小，点击区域仅约 16px
- 修复：`min-height: 80rpx`、`padding: 20rpx 16rpx`、`box-sizing: border-box`

### 五、浏览历史"商品已下架"修复（v1.2.1 已修，本次含云函数部署）
- 历史页补充商品信息时对匹配不到的商品调用 `getProductDetail` 兜底

### 六、商品分享图片修复（v1.2.1 已修，本次含云函数部署）
- 分享图片 URL 做 `encodeURI` 编码空格，防防盗链回退微信自动截图

### 七、商品分享图片裁剪修复
- 原因：微信分享卡片要求 5:4 宽高比，LV 官网图片是 1:1 正方形，被强制裁剪后只显示底部
- 修复：不指定 imageUrl，让微信自动截取页面截图，商品图完整可见

## v1.2.1（2026-10-01）

> 浏览历史与商品分享 Bug 修复。

### 一、浏览历史"商品已下架"显示修复
- 原因：商品总数约 4 万条，历史页补充商品信息时仅获取前 100 条，导致不在前 100 的商品匹配不到名称，被误显示为"商品已下架"
- 修复：对列表匹配不到的商品，按需调用 getProductDetail 获取详情补充名称和图片

### 二、商品分享图片无法显示修复
- 原因：分享图片使用 LV 官网原图 URL，URL 中含空格导致微信服务端拉取失败，且 LV 防盗链可能拦截微信服务端请求
- 修复：对分享图片 URL 做 encodeURI 编码空格；非 https 或为空时不指定 imageUrl，由微信自动截取页面截图作为分享封面

## v1.2.0（2026-09-28）

> 四个 Tab 页面设计规则统一与布局细节优化。

- 涉及比价、计算器、工具、我的四个 Tab 页面

### 二、计算器、工具 Tab 导航栏与间距统一
- 导航栏与首个卡片内容垂直距离统一为 `8px`
- 导航栏高度向下增加 `4px`，视觉比例更协调
- 工具 Tab 移除原浅灰色延伸条（`::after`），改为 `border-bottom: 1rpx`，与计算器 Tab 样式一致
- 修复导航栏 `position: fixed` 被全局 `position: sticky` 覆盖导致间距异常的根因：在 WXML 内联样式中写死 `position: fixed`，确保脱离文档流
- 工具页导航栏标题改为「汇率计算工具」

### 三、比价 Tab 布局微调
- 搜索栏及标签向下移动 `8px`，避免与顶部内容拥挤
- 商品列表模块向上移动 `4px`，提升首屏信息密度
- 左上角「比惠」文字与右侧小程序胶囊按钮下对齐（动态计算 headerInnerHeight，`align-items: flex-end`）

### 四、我的 Tab 黑色用户信息区域减扁
- 黑色区域底部内边距从 `72rpx` 减为 `32rpx`，减少纵向空间占用
- 数据统计区与用户信息区间距从 `40rpx` 减为 `24rpx`，布局更紧凑

## v1.1.5（2026-09-22）

> 浏览历史与我的收藏交互重构。

### 一、浏览历史页重构

**1. 显示具体浏览商品**
- 历史记录由纯文字改为商品卡片：展示商品图片、品牌、名称、中国价/日本价
- 修复历史列表不渲染问题（原列表依赖未赋值的分组字段，导致只有"共 N 条"而无内容）

**2. 清理改为多选删除**
- 点击「清理」进入多选模式，勾选一条或多条记录后点击底部「删除 (N)」批量删除
- 支持二次确认弹窗，防止误删
- 取消左滑删除交互（移除相关提示）

**3. 修复删除失效**
- 修复历史删除接口调用方法名错误（request.delete → request.del），清空/删除不再报错
- 云函数新增 removeHistories 批量删除能力（单次调用即可删除多条，避免逐条请求）

### 二、我的收藏改为独立页面

**1. 收藏从我的 tab 移出**
- 移除「我的」页顶部的收藏商品预览卡片，收藏商品不再直接显示在 tab 中
- 保留收藏数量统计与菜单角标

**2. 独立收藏页**
- 点击「我的收藏」菜单或统计区「收藏」进入独立收藏页（原页面跳转失效，仅滚动到页内）
- 收藏页展示商品卡片（图片/品牌/名称/价格），并可点击进入商品详情
- 右上角「管理」进入多选模式，底部「删除 (N)」批量取消收藏，支持二次确认
- 云函数新增 removeFavorites 批量删除能力

### 三、商品名称显示修复（本轮修订补充）

**1. 修复部分商品不显示名称（列表页 + 详情页）**
- 原因：数据源约 133 件商品（占 23%）仅捕获韩文名（nameKr），中/日/英名全空，导致列表与详情均无名称
- 处理（无需重新导入数据，重新部署云函数即生效）：
  - 云函数 getProductList/getProductDetail 增加名称兜底：优先从韩文名括号提取英文名（如 "알마 PM (Alma PM)" → "Alma PM"），其次从主图 URL 规范 slug 提取（如 louis-vuitton-alma-mm → Alma MM）
  - 前端列表（比价/商品列表）与详情页 displayName 增加 nameEn 兜底，全空时显示「货号」避免空白
  - 收藏页/历史页同样加入名称推导兜底
  - 本地数据 full_import_data.json 的 nameEn 字段已同步补全（133 件），console_import 导入文件已重新生成，供下次重导使用

**2. 统一商品详情页信息字体格式**
- 补齐详情页缺失的样式类（副名称、品牌标签、货号行），统一规范：
  - 商品名称：40rpx 粗体 #1A1A1A；副名称：26rpx 灰色
  - 品牌标签（右上）：22rpx 灰色；货号：24rpx 灰色
- 修复不同商品名称字体/大小/样式不一致问题

**3. 修复收藏页/历史页导航栏安全区错位**
- 原因：两页导航栏用 `env(safe-area-inset-top)` 计算顶部安全距离，微信小程序顶部该变量恒为 0，导致导航栏顶入状态栏、标题被灵动岛遮挡、返回按钮与件数位置错乱
- 处理：改为与其他页面统一的标准实现——JS 读取 `statusBarHeight` 内联到导航栏 padding-top，导航内容（返回/标题/计数）置于 88rpx 导航区内并垂直居中

**4. 比价页搜索后增加返回首页路径**
- 搜索框新增「刷新」键（↻）：点击即清空关键词并恢复比价首页默认列表；无关键词时为刷新
- 删除搜索框内容后自动回到比价首页（恢复默认列表）

**5. 商品名称校准与缺名过滤**
- 取消「货号」作为商品名称显示（不再出现"货号 P01926"式名称）
- 无真实名称的商品：比价页/分类页默认列表不展示；搜索场景不过滤（仍可搜到），缺名显示「暂无名称」
- 名称推导兜底继续生效：韩文名括号英文（如"알마 PM (Alma PM)"→Alma PM）或主图 URL slug 提取英文名
- 本地数据 133 条缺名商品 nameEn 已全部补全（三语名全空商品数=0），console_import 导入文件已更新

**6. 统一全部二级页面导航样式**
- 9 个二级页（商品列表、商品详情、我的收藏、浏览历史、隐私政策、关于比惠、意见反馈、商品对比、价格提醒）统一为参考图标准：
  - 返回按钮：圆形浅灰底（#F5F3F0）+ 深色箭头，位于导航栏左上
  - 标题：水平居中、32rpx 加粗，不与胶囊重叠
  - 顶部安全区：JS 读取 statusBarHeight 内联传入，导航内容置于状态栏下方 88rpx 区
  - 底部分割线 1rpx
- 修复：隐私政策/商品对比/价格提醒三个页面此前无返回入口，现已补全

### 四、版本号统一管理
- 新增 `utils/version.js` 作为版本信息唯一来源：「我的」tab 底部版本号、「关于比惠」页版本号与应用简介均从此处读取
- 版本号需与本版本提交上线版本号一致（当前 v1.1.5）
- 关于页不展示更新日志区块；版本迭代内容统一记录于本更新记录文档

### 四、版本号与关于页内容维护约定
- 后续每次修订/功能迭代，按以下规则自动递增版本号并同步更新 `utils/version.js`：
  - 修复 Bug / 小优化：patch +1（如 1.1.4 → 1.1.5）
  - 新增功能 / 功能迭代：minor +1（如 1.1.5 → 1.2.0）
  - 重大重构 / 整体升级：major +1（如 1.2.0 → 2.0.0）
- 每次发版需同步维护三处：`utils/version.js`（版本号 + 更新日志 + 简介）、本更新记录文档、微信后台提交版本号保持一致
